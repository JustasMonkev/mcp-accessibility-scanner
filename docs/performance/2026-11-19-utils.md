# Shared utility performance

Compared with `9ec0e20` on Linux x64, Node 24.22.3. The browser measurements use Playwright 1.65.1 and Chrome Headless Shell 159.0.8154.6. All timings are wall-clock medians on one host. [Raw timing samples](2026-11-19-utils.json)

[Complete function inventory, callback timings and before/after benchmarks](2026-11-19-all-utils.md)

## Browser measurements

| MCP call | Before (ms) | After (ms) | Speedup |
| --- | ---: | ---: | ---: |
| First console read, four whitespace-heavy SVGs | 106.6 | 15.9 | 6.72× |
| Full heavy-page Axe scan | 2,187.6 | 1,596.5 | 1.37× |

The heavy-page scan run medians were 1841.3 and 2221.4 ms on the baseline and 1245.7 and 1675.7 ms on the candidate. An earlier 15-call baseline run had a 1,492.1 ms median, inside the range of candidate run medians. The pooled comparison alone cannot establish a scanner-wide speedup.

Each row pools ten timed MCP calls per revision across four process launches in baseline, candidate, candidate, baseline order. Each launch gets one warm-up and five timed calls. The console fixture logs four raw SVGs, each containing 1,024 consecutive spaces inside a text node. Setup, navigation and typing are outside the timer. The benchmark verifies that all four messages retain their suffix after truncation. The scan row uses the existing heavy-page Axe fixture.

## Scope

| Helpers reviewed | Work performed |
| --- | --- |
| ARIA compression | Bypass parsing below the repeat threshold. Build parent and protection state in one forward pass, propagate protection to ancestors, and reuse group counts during rendering. |
| Data URL truncation and console formatting | Scan directly to raw payload delimiters, consume horizontal whitespace runs together, and decode encoded metadata once. The first-read MCP benchmark includes console formatting. |
| UTF-8 truncation and download-error markers | Inspect only the prefix that can fit the byte budget. Detach the returned prefix so a small stored error can release its large input. |
| HTML tokens, semantic signatures, edit distance, and pattern grouping | Remove a redundant token match, retain only root attributes used in the signature, and compare only the differing portions of token arrays. Grouping uses these helpers directly. |
| Representative URL selection | Skip query parsing for plain paths, bypass allocation tables for terminal and single-branch nodes, and reconstruct only the selected budget. |
| Code generation and function-source recognition | Reuse JSON string escaping for double-quoted labels and scan a parenthesized expression once per enclosing layer. Object formatting and single-quoted snippets keep their original formatting. |
| Hashes and random identifiers | Use one-shot SHA-256 for fingerprints. Both GUID generators still draw cryptographically random bytes. |
| Filename sanitization and timestamps | Keep the filename rules, millisecond timestamp, and random suffix. |
| URL redaction | Keep escaping and matching rules, structured-result serialization and disabled-mode identity. |
| HTTP URL checks, errors, logging, terminal output, package metadata | These perform a protocol comparison, error conversion, I/O delegation or a one-time module read. |
| CDP connection and timeouts | Preserve transport setup, message filtering, timer disposal and abort behavior. These operations depend on browser, socket or timer latency. |

## Reproduce

From the candidate checkout, build the baseline and candidate with the same lockfile and Node version. The command examples assume the baseline checkout is at `../baseline`.

```sh
npm run build
node bench/shared-utils.mjs ../baseline/lib/utils lib/utils
node bench/mcp-bench.mjs --only 'browser_console_messages (raw SVG' --iterations 5 --warmups 1 --executable-path "$CHROME_HEADLESS_SHELL"
node bench/mcp-bench.mjs --only 'scan_page (axe)' --iterations 5 --warmups 1 --executable-path "$CHROME_HEADLESS_SHELL"
```

To measure the baseline using exactly the same browser fixtures, append `--server ../baseline/cli.js --lib ../baseline/lib` to the MCP commands. Use `--out results.json` to save the individual samples.
