# Performance measurements — 2026-10-28

The 10× end-to-end goal was not achieved. The final change speeds up data-URL parsing on malformed prose and long metadata. The sum of 19 normal tool-scenario medians changed from **22,947.3 ms to 23,242.2 ms (+1.28%)**, so this run demonstrates no overall tool-latency improvement.

The retained production change is confined to `src/utils/dataUrl.ts`. Delimiter scanning now stops at raw whitespace and wrappers that the existing metadata validator already rejects, instead of repeatedly scanning the rest of a long line. A native regular expression finds delimiter candidates. Encoded metadata, query boundaries, long valid metadata and output contents retain their existing behavior.

## Parser measurements

Both compiled builds run in the same process, with alternating order, 5 warmups and 20 timed samples per input. Every call asserts the expected output outside the timer. These are synthetic function timings; the 946× result applies to the 48 KB malformed-prefix fixture.

| Input | Baseline median (ms) | Final median (ms) | Speedup |
| --- | ---: | ---: | ---: |
| malformed prefixes (400) | 11.563 | 0.060 | 192.85× |
| malformed prefixes (2000) | 347.744 | 0.367 | 946.53× |
| valid long metadata (32 KB) | 0.354 | 0.100 | 3.53× |
| ordinary text with valid data URLs (2000 lines) | 1.136 | 1.273 | 0.89× |

The mixed ordinary/valid-URL case regressed by approximately 0.137 ms per 2,000-line input in this run. The change does not establish a linear bound for every malformed input: delimiter-free strings without rejected metadata characters can still trigger repeated suffix scans.

No scan-engine optimization is included in the final code.

## Environment and validation

- Baseline: `c8c27a979a9a69753befd63482d92e530903a309`.
- Node 24.22.1; Playwright 1.63.0; axe-core 4.14.0; Linux x64 6.18.55; AMD EPYC 9V74; 8-CPU quota and 8 GiB memory limit.
- Chrome Headless Shell 153.0.8010.12, the pinned Playwright browser version. The archive came from the official Google Chrome for Testing endpoint; its SHA-256 is recorded in the environment report.
- Build, lint/typecheck, Knip and Slop-check passed. Slop-check reported no findings on the changed code; manual review found no contract changes.
- Final `npm test`: **1,847 passed, 5 skipped, 2 failed**. Both failures are in `tests/cdp-frame-tree.integration.test.ts:78`, where browser-fixture setup expects an out-of-process iframe CDP target. Both reproduce on the untouched baseline before scanner code runs. Full pinned Chromium cannot start here (`socket() failed: Operation not permitted`); the available headless shell does not supply that fixture's expected target. No tests or assertions were weakened.
- The parser's targeted suite passed 102 tests. A seeded differential corpus produced 20,000 identical baseline/candidate comparisons. A manual mutation breaking comma recognition failed the tests; the mutation was reverted.

## Reproduce

From the candidate checkout, build both revisions and use the same browser executable for both runs:

```bash
git worktree add --detach /tmp/mcp-a11y-before c8c27a979a9a69753befd63482d92e530903a309
(cd /tmp/mcp-a11y-before && npm ci && npm run build)
npm ci
npm run build
BENCH_BROWSER=/path/to/chrome-headless-shell
npm run bench -- --server /tmp/mcp-a11y-before/cli.js --lib /tmp/mcp-a11y-before/lib --executable-path "$BENCH_BROWSER" --iterations 5 --warmups 1 --out before.json --label before
npm run bench -- --executable-path "$BENCH_BROWSER" --iterations 5 --warmups 1 --out after.json --label after
npm run bench:compare -- before.json after.json
node bench/data-url-bench.mjs /tmp/mcp-a11y-before/lib/utils/dataUrl.js lib/utils/dataUrl.js > data-url-comparison.json
```
